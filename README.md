# TerminalV

Терминал для Windows с **вертикальными вкладками**. Каждая вкладка — отдельная сессия PowerShell через ConPTY, экран рисует xterm.js.

## Установка

В PowerShell:

```powershell
irm https://raw.githubusercontent.com/XYphrodite/TerminalV/main/install.ps1 | iex
```

Скрипт скачивает последний релиз, проверяет SHA-256 из файла `.sha256`, устанавливает в `%LOCALAPPDATA%\Programs\TerminalV`, добавляет каталог в пользовательский PATH и создаёт ярлык в меню Пуск. Права администратора не нужны.

При установленном .NET 10 Desktop Runtime автоматически выбирается облегчённая framework-dependent сборка. Параметр `-Variant light` или `-Variant full` задаёт вариант явно; последующее самообновление сохраняет этот выбор.

Перед переустановкой закройте окно TerminalV. Фоновый host и его сессии могут продолжать работать: установщик их не завершает. Прежние файлы пакета перемещаются в `.terminalv-backup-*` внутри каталога установки; при ошибке проверки новой копии выполняется откат. База сессий и данные WebView2 сохраняются.

Другой каталог или конкретная версия:

```powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/XYphrodite/TerminalV/main/install.ps1))) -InstallDir 'D:\TerminalV' -Version v0.1.0
```

Ярлык в меню «Пуск» создаётся по умолчанию. Рабочий стол — только по желанию, с параметром `-DesktopShortcut`:

```powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/XYphrodite/TerminalV/main/install.ps1))) -DesktopShortcut
```

Параметры: `-InstallDir`, `-Version` (по умолчанию latest), `-NoPath`, `-DesktopShortcut`, `-NoShortcut` (не создавать никаких ярлыков, даже с `-DesktopShortcut`; существующие не удаляются).

Ручная установка: zip `TerminalV-win-x64.zip` со [страницы релизов](https://github.com/XYphrodite/TerminalV/releases). Сборка self-contained, отдельно ставить .NET не нужно. Нужен [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) — на Windows 11 он уже есть вместе с Edge.

После распаковки ZIP запустите `TerminalV.exe` → **Настройки** (шестерёнка или `Ctrl+,`) → **Ярлыки приложения**. Выберите «Меню „Пуск“» и/или «Рабочий стол», затем нажмите **Создать ярлыки**. Нужные папки определяются через Windows, включая перенесённый рабочий стол OneDrive. Ярлыки ведут к текущей копии приложения и используют иконку из её EXE; права администратора не нужны.

Повторное создание обновляет иконку без дубликатов и сохраняет пользовательские настройки существующего ярлыка. Если `TerminalV.lnk` указывает на другую копию или содержит аргументы, он не перезаписывается: интерфейс покажет причину. Перед переносом ZIP-папки уберите старые ярлыки или переименуйте их, затем создайте новые. При запуске/самообновлении приложения удалённые ярлыки не восстанавливаются автоматически; закрепление на панели задач остаётся за пользователем.

Запуск после установки:

```powershell
TerminalV
```

Установленная копия сама проверяет GitHub Releases при старте. Если есть более новая версия, слева появляется кнопка **Обновить**. Из любой оболочки, в том числе из вкладки TerminalV:

```powershell
TerminalV update --check
TerminalV update
```

Если окно уже открыто, команда ставит файлы и перезапускает окно; сессии остаются в фоновом процессе. Скачанный zip сверяется с SHA-256, новый exe отвечает на `--help` до замены и после. Сборка 0.1.0 обновление не умеет — её один раз ставят через `irm`.

Из исходников после `dotnet build`: `src\TerminalV\bin\Debug\net10.0-windows\TerminalV.exe`.

## Сборка из исходников

Нужны .NET 10 SDK, Node.js и npm.

```powershell
dotnet build
dotnet run --project src/TerminalV
```

Релизная папка (self-contained `win-x64`, `TerminalV.exe`, консольный `TerminalV.com` и `wwwroot`):

```powershell
.\scripts\publish.ps1
```

Артефакты: `artifacts/TerminalV-win-x64.zip` и `.sha256`. Прежние файлы не удаляются и не перезаписываются. Если архив уже существует, укажите новый каталог:

```powershell
.\scripts\publish.ps1 -OutputDirectory artifacts\candidate-01
.\scripts\verify-package.ps1 -Package artifacts\candidate-01\TerminalV-win-x64.zip
```

Упаковка использует отдельную свежую папку `.publish-*` и сохраняет её для диагностики. Проверка пакета оставляет логи и распакованные файлы в `verification-*` рядом с ZIP: контрольная сумма, состав, CLI, изолированное обновление/откат, ConPTY, SQLite и браузерные тесты интерфейса из архива. По умолчанию ожидается версия из проекта; для другого пакета есть `-ExpectedVersion`. Проверка не запускает рабочее окно, не использует пользовательскую базу и не публикует релиз. Для полной проверки PowerShell 7 задайте `TERMINALV_TEST_PWSH`, если он не установлен в стандартном каталоге.

Проверка ConPTY без окна:

```powershell
.\src\TerminalV\bin\Debug\net10.0-windows\TerminalV.exe --smoke
```

Регрессионные проверки интерфейса (нужен установленный Edge или Chrome):

```powershell
npm.cmd --prefix ui test
```

Изолированные проверки рабочей папки, запуска профилей PowerShell/cmd, настоящего ConPTY и протокола фонового процесса:

```powershell
dotnet run --project tests/TerminalV.Pty.Tests -c Release
```

Тесты не загружают пользовательские профили и не подключаются к рабочему фоновому процессу TerminalV. Они запускают Windows PowerShell 5.1 и, если доступен, PowerShell 7 из `Program Files\PowerShell\7`. Для portable PowerShell 7 можно задать путь к `pwsh.exe` через `TERMINALV_TEST_PWSH`; при его отсутствии эта часть явно пропускается.

Проверки миграции базы, групп, скрытых сессий, отключения звука, профилей и расположения панелей на временных SQLite-файлах (рабочая база пользователя не используется):

```powershell
dotnet run --project tests/TerminalV.Data.Tests -c Release
```

## Что умеет v0.5.3

- Вертикальный список вкладок слева
- PowerShell 7 (`pwsh`), иначе Windows PowerShell
- Несколько независимых сессий
- Переименование вкладки (двойной клик)
- Копирование и вставка, в том числе правой кнопкой
- Предупреждение с предпросмотром перед многострочной вставкой
- Самообновление: кнопка в сайдбаре и `TerminalV update`
- Темы, шрифт, фон-фото, сворачиваемый список сессий, масштаб как в VS Code
- Сессии сохраняются в SQLite

## Новое в v0.5.0

- Поиск по выводу, защита закрытия работающей сессии и наследование текущей папки.
- Группы, цветовые метки, закрепление, фильтр и скрытые сессии.
- Настраиваемые уведомления BEL с подсветкой и ограничением частоты.
- [Профили запуска](docs/usage.md#профили-запуска): оболочка, папка, название, цвет и стартовая команда, без повторного выполнения при подключении к живой сессии.
- [Разделение экрана](docs/usage.md#разделение-экрана-на-панели): панели справа/снизу, изменение размеров, переключение клавиатурой и восстановление расположения без перезапуска живых сессий.
- Более безопасное обновление: проверка комплектности ZIP, замена консольного запускателя, откат и защита служебных путей.

После обновления старый фоновый процесс может продолжать обслуживать рабочие сессии. Для профилей и интеграции текущей папки при соответствующем предупреждении сохраните работу и перезагрузите Windows. Простое закрытие окна не обновляет фоновый процесс.

Порядок дальнейшей работы — [план фич](docs/feature-plan.md).

## Новое в v0.5.1

Обновлённое оформление: единые SVG-иконки, более читаемые сессии, заголовок с текущей папкой, аккуратные панели и диалоги, превью десяти тем и компактный список без пустого отступа. Настройки удерживают фокус и изолируют сочетания клавиш от терминала. Сохранённые темы, шрифты и сессии совместимы. Подробности — [заметки к релизу](docs/releases/v0.5.1.md).

## Новое в v0.5.2

Меню **Профили и оболочки** запускает сохранённый профиль сразу, без редактора и повторного сохранения. Редактирование и создание — отдельные действия. Windows-оболочки и установленные дистрибутивы WSL обнаруживаются автоматически; **Ubuntu** запускается прямо в новой вкладке из домашней папки Linux. Подробнее — [быстрый запуск WSL](docs/usage.md#быстрый-запуск-wsl).

Новые сессии получают актуальное окружение Windows: недавно установленные Codex и другие команды находятся по обновлённому `PATH`. Уже работающие сессии не меняются. При первом переходе со старого фонового процесса сохраните работу и перезагрузите Windows — закрытие одного окна хост не обновляет. Подробности — [заметки к релизу](docs/releases/v0.5.2.md).

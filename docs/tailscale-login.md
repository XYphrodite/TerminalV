# Вход через Tailscale

Для нового режима нужны обновлённые приложения на телефоне и на ПК. Android-клиент входит в Tailscale через браузер, обнаруживает работающие шлюзы TerminalV на доступных Windows-узлах и открывает существующие сессии после подтверждения на ПК. Пароль Windows, SSH-ключ и токен шлюза для этого режима не нужны.

## Использование

1. Запустите новую Windows-версию TerminalV. На ПК должен быть установлен и авторизован Tailscale. В настройках TerminalV включите шлюз; стандартный порт — 5454.
2. На телефоне откройте «Подключение» → «Войти через Tailscale». Завершите вход в системном браузере и вернитесь в приложение. Если в tailnet включено одобрение устройств, подтвердите новое устройство в панели Tailscale.
3. Выберите компьютер. Подтвердите аккаунт и имя телефона в отдельном окне TerminalV на ПК. Разрешение даёт доступ к выводу и выполнению команд с правами запущенного TerminalV.
4. Существующие сессии появятся на телефоне. Новые вкладки создаются на выбранном ПК.

Телефон получает список вкладок ПК вместе с названиями, порядком и признаком скрытой сессии. Скрытые вкладки остаются скрытыми; фоновые процессы без вкладки не добавляются в список. После успешного обновления списка старые мобильные записи не подмешиваются к нему. При потере связи сохраняется последний полученный список с доступным локальным выводом.

Согласование уже открытого списка и размеров общего терминала требует пары Android **1.1.6** / Windows **0.7.16**. Пока приложение видно, каталог проверяется каждые 15 секунд и при возвращении из фона. Старые мобильные снимки архивируются без завершения процессов ПК. Размер общей сессии задаёт десктоп, а телефон прокручивает её видимую область; подробности — в [описании мобильных сессий](mobile-sessions.md#размер-общего-терминала).

Если ПК не находится, проверьте порт (в мобильном окне есть «Другой порт шлюза»), правила доступа Tailscale и статус шлюза на ПК. Для первоначальной настройки HTTP.sys и Windows Firewall можно один раз запустить `scripts/enable-tailnet-gateway.ps1` от администратора под учётной записью пользователя TerminalV. Он разрешает входящий трафик только между Tailscale-адресами. После этого перезапустите TerminalV. Для нестандартного порта используйте `-Port`.

Для диагностики обнаружения используется `GET /terminalv/info` с заголовком `Authorization: Tailscale` между адресами tailnet. Совместимый шлюз возвращает JSON с `protocol: terminalv-tailnet-v1`, именем ПК и `approved: false` до подтверждения телефона. `HTTP 426` на этом пути означает старую Windows-сборку без API обнаружения; одного обновления APK недостаточно. `HTTP 401` означает, что Tailscale-личность запроса не принята. В частности, проверка с узла с `tag:` не заменяет проверку с пользовательского телефона: служебные устройства намеренно отклоняются.

Окно ПК и шлюз используют общее подключение к фоновому процессу сессий: уже запущенный процесс допускает только одного клиента. Попытка шлюза открыть второй канал приводила к пустому списку сессий и ошибке «Resize не удался». История для нового мобильного подключения передаётся из отдельного буфера шлюза только этому подключению; повторное подключение не дублирует вывод в других окнах. Для этой правки достаточно обновить Windows-приложение, сохранив работающий процесс сессий.

## Доступ и отзыв

- Шлюз получает личность от локального `tailscaled` через `tailscale whois --json` для реального адреса TCP-соединения. Переданные телефоном заголовки с логином не являются удостоверением личности.
- Запрос принимается только между адресами Tailscale. Метки узлов (`tag:`) не считаются пользовательским входом. Недоступность локального Tailscale приводит к отказу в доступе.
- Подтверждение хранится для пары стабильного ID устройства и ID пользователя в `%LocalAppData%\TerminalV\tailnet-devices.json`. Другое устройство или другой аккаунт требуют отдельного подтверждения.
- «Отозвать доступ телефонов» в настройках ПК удаляет разрешения и закрывает активные соединения этого режима. Доступ по прежнему ручному токену настраивается отдельно.
- «Выйти из Tailscale» на телефоне закрывает мобильные соединения и завершает вход. Сами сессии на ПК продолжают работать.
- Ключи нового входа хранятся в приватном каталоге Android `no_backup`; они не входят в экспорт настроек TerminalV и стандартное резервное копирование приложения.

Ручное подключение SSH/токеном остаётся в раскрывающемся разделе. Новая авторизация не меняет SSH-политику компьютера. Членство в tailnet само по себе не разрешает доступ к терминалам: необходимо подтверждение на ПК.

## Проверки

`tests/TerminalV.Ssh.Tests` проверяет отсутствие доступа до подтверждения, сохранение и отзыв разрешений, изоляцию пользователей и устройств, отклонение поддельных заголовков и tagged-узлов, WebSocket через подключаемый транспорт и закрытие соединения после отзыва. `tests/TerminalV.Mobile.Tests` проверяет восстановление существующих сессий и ввод через шлюз. Сборка AAR выполняется `tools/tsnet-bridge/build-aar.ps1` на Xeon.

Полный пользовательский вход в браузере требует реального аккаунта Tailscale и подтверждения устройства/доступа. Эти действия не подменяются тестовой авторизацией и не выполняются автоматически от имени пользователя.

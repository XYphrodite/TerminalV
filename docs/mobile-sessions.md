# Мобильные сессии

Мобильный клиент использует общий интерфейс `ui/` и xterm.js в MAUI BlazorWebView. Сообщения идут через `window.__terminalvHost` → `DotNetObjectReference<Home>` → `MobileBridge` → `SshService`. Обратный поток доставляется через `__tvDispatch`. Нативный `chrome.webview`, который нужен самому Blazor, не подменяется.

Прямой SSH и SSH через Tailscale вызывают `Flush()` после каждой записи в `ShellStream`: байтовый `Write` в SSH.NET оставляет короткий ввод в буфере. Регрессионные проверки используют буферизованный поток и проверяют доставку отдельных символов, кириллицы, Enter, Backspace и Ctrl+C сразу после `WriteAsync`. Ввод в завершённую вкладку игнорируется до явного перезапуска; сохранённый вывод может содержать ошибку предыдущего подключения. Версия в интерфейсе берётся из установленного приложения.

В режиме шлюза `GatewayControlClient` получает список сессий ПК до отправки `init`. Интерфейс создаёт вкладки и посылает `attach`; только после этого `GatewaySshSession` подключается к существующей сессии и получает её вывод. Подтверждённый каталог ПК определяет состав вкладок, названия, порядок и признак скрытой сессии, в том числе при повторном `init`. Текущая вкладка телефона остаётся выбранной, пока она присутствует среди открытых вкладок; исправное подключение не пересоздаётся при обновлении метаданных. Сохранение настроек подключения пересоздаёт транспорт, сохраняя работающие оболочки на ПК. Ошибки списка сессий отображаются над терминалом, ошибки подключения отдельной сессии — в её вкладке.

Старые мобильные записи, отсутствующие в подтверждённом каталоге, убираются из списка. Их локальные снимки сохраняются отдельно в `terminalv_archived_sessions` и входят в JSON-экспорт как `archivedSessions`; очистка представления не отправляет `kill` на ПК. При неудачном запросе каталога сохраняются прежний список и вывод. Устаревший шлюз без метаданных использует прежний режим списка идентификаторов.

Подключение открывается из блока компьютера над «Новая вкладка» в боковой панели. Блок показывает выбранный компьютер и состояние связи; он не перекрывает терминал и версию приложения. Состояние обновляется по результату обращения к шлюзу и событиям SSH, а при открытии списка сессий или параметров подключения шлюз проверяется повторно. Пока приложение видно на экране, выбранный шлюз проверяется каждые 15 секунд; возвращение из фона запускает проверку сразу. В скрытом WebView и после выхода опрос не выполняется. Сохранённый адрес и сам вход в Tailscale не считаются активным подключением.

Проверка обновляет интерфейс при изменении каталога или потере мобильного транспорта существующей живой сессии. Во втором случае даже неизменившийся список позволяет повторно присоединить потерянное зеркало; исправные подключения остаются на месте. Результат проверки старого подключения не применяется после переподключения или выхода.

## Размер общего терминала

Для согласования списка и размеров терминала нужны Android **1.1.6** и Windows **0.7.16** вместе. Windows-сборка содержит эти изменения поверх исправлений 0.7.15; более старый APK не умеет использовать передаваемые размеры общего терминала.

У одной сессии PTY одна сетка строк и столбцов. Когда сессия открыта на ПК, размер задаёт окно ПК, а телефон получает ту же сетку перед выводом и при её изменении. Открытие экранной клавиатуры или узкой мобильной панели не уменьшает PTY на десктопе. Поэтому TUI-приложения не должны попеременно перерисовываться под размеры двух устройств.

На телефоне большой терминал показывается как область с прокруткой: горизонтальный жест перемещает видимую часть по ширине, вертикальный — по высоте, если полный экран терминала не помещается. На границе этой области остаётся обычная прокрутка истории xterm. Для прямого SSH размер по-прежнему следует за экраном телефона.

Для шлюза доступно «Переподключиться» в параметрах выбранного компьютера. Для прямого SSH сохранённую сессию перезапускают кнопкой «Перезапустить» в терминале. Открытие и закрытие параметров не ждёт завершения сетевых операций терминала. На узком экране свёрнутый список можно открыть видимой кнопкой «Сессии» или свайпом от левого края.

Android использует `WindowSoftInputModeAdjust="Resize"` и `SafeAreaEdges="SoftInput"`: экранная клавиатура уменьшает область WebView, а не перекрывает её. Это сохраняет прокрутку до нижних кнопок подключения и доступную высоту терминала в полноэкранном режиме. Сам диалог дополнительно учитывает `visualViewport`.

Режим и токен берутся из экрана подключения. Настройки серверного шлюза, отзыв доступа телефонов и ярлыки Windows в мобильном интерфейсе скрыты: шлюз запускается на ПК, а не на телефоне. Оформление терминала, WebGL и резервное копирование остаются доступны.

На телефоне меню «Профили» не ищет локальные оболочки Windows и дистрибутивы WSL. У профиля доступны название и цвет; оболочка, стартовая папка и команда скрыты, поскольку текущий мобильный транспорт их не применяет. Существующие значения этих полей в сохранённых профилях не удаляются.

В боковой панели показывается версия установленного клиента: мобильная — из метаданных APK, десктопная — из сборки Windows. Эти версии могут отличаться. Мобильный клиент сообщает свою версию до подключения к шлюзу, поэтому она доступна и без сети. До получения метаданных вместо устаревшего номера отображается «…». Номер мобильной версии не запускает проверку обновлений Windows.

SSH поддерживает парольный `keyboard-interactive` наряду с методом `password`; пароль подставляется только в распознанный скрытый запрос пароля. Одноразовые коды и браузерное подтверждение этим обработчиком не поддерживаются. Это не обходит настройки сервера: при `PasswordAuthentication no` на Windows нужен ключ или изменение серверной политики. Windows OpenSSH может объявлять неподдерживаемый `keyboard-interactive` ([описание проблемы](https://github.com/PowerShell/Win32-OpenSSH/issues/1554)).

Для изолированной проверки парольного `keyboard-interactive` соберите `tests/TerminalV.Ssh.Tests/keyboard-server.go` из Go-модуля `tools/tsnet-bridge` и запустите с путём к файлу порта первым аргументом. Сервер слушает только localhost и использует тестовые данные `test` / `test-password`. Передайте прочитанный порт через `TERMINALV_TEST_SSH_PORT` тестам `TerminalV.Ssh.Tests`: они проверяют настоящий SSH-вход и эхо ввода обоими клиентами. Для клиента Tailscale только транспорт подменяется локальным TCP; эта проверка не авторизует устройство в tailnet. После теста завершите процесс тестового сервера.

`CopyDesktopUi` собирает Vite и копирует актуальные ресурсы через `ui/scripts/copy-mobile-ui.js`. Мобильный HTML использует постоянные имена `assets/mobile.js` и `assets/mobile.css`, поэтому смена хешей Vite не оставляет ссылок на старую сборку.

Для Android также обязателен `Platforms/Android/libs/tsnet.aar`. Он не хранится в Git и собирается на Xeon перед публикацией:

```powershell
.\tools\tsnet-bridge\build-aar.ps1 -AndroidSdk C:\AndroidSDK
```

Сборка останавливается, если AAR отсутствует. После публикации запустите `scripts/verify-mobile-apk.ps1 -Apk <путь-к-APK>`: проверка сверяет UI с текущими файлами, ищет `tsnet.Tsnet_` в DEX и `libgojni.so` для ARM64/x86_64. Одного успешного `dotnet publish` недостаточно для проверки комплектации APK.

Проверки:

```powershell
dotnet run --project tests/TerminalV.Mobile.Tests -c Release
dotnet run --project tests/TerminalV.Ssh.Tests -c Release
npm.cmd --prefix ui test
```

Мобильные C#-тесты используют реальный WebSocket-клиент и сервер с тестовым backend. Они также проверяют состояние подключения, потерю связи без открытых сессий, согласование каталога, сохранение архива и восстановление потерянного зеркала при неизменившемся каталоге. Запоздалые события после смены транспорта или выхода не должны менять актуальное состояние. Настройки MAUI заменены памятью, рабочие сессии и база пользователя не используются.

Браузерный тест загружает мобильный HTML, собранные ресурсы и реальный JS-мост с тестовым Blazor-компонентом. Он проверяет добавление сессий, замену старого списка при втором `init`, скрытые вкладки, вывод, ввод с экранной клавиатуры, состояние боковой панели, фокус и блокировку горячих клавиш за открытым подключением. Проверяются ширина 320px и прокрутка до нижних кнопок при высоте 280px. Реальные Android-клавиатура и Blazor-диалог требуют проверки установленного APK; соединение с пользовательским ПК — отдельной проверки через его шлюз. Описание набора проверок само по себе не подтверждает их прохождение для конкретной сборки.

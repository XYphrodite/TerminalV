# Сохранение сессий

Список вкладок, метаданные, снимки xterm и расположение панелей передаются из `ui/src/main.js` в `TerminalBridge`. `AppDatabase.SaveSessions` записывает список и расположение одной транзакцией SQLite. Работающие процессы отдельно живут в `SessionHost`; снимок экрана нужен после их завершения или перезагрузки Windows.

## Исправленные причины потери данных

- `terminalvFlush` разрешал сохранение до получения `init`. Быстрое закрытие могло записать пустой список вместо существующего. Теперь до загрузки отправляется только `flush-skipped`, без записи сессий и настроек.
- Восстановление передавало сохранённый текст в асинхронный `xterm.write`, а затем сразу сериализовало ещё пустой терминал. Теперь сохранение ждёт обработки уже принятых данных всех вкладок, включая скрытые. До поступления вывода живой сессии используется последний снимок из базы.
- Каждая порция вывода сбрасывала таймер на 400 мс. Поток логов мог откладывать сохранение неограниченно. Сохранилась задержка для коротких серий, но добавлен максимальный интервал ожидания 2 секунды.
- Закрытие ждало 80 мс после запуска JavaScript, не проверяя запись. Теперь запрос закрытия имеет идентификатор; `TerminalBridge.FlushAsync` завершается после соответствующего `SaveSessions`. Ошибка записи настроек или сессий отменяет закрытие и попадает в `diagnostics.log`. Время ожидания ответа ограничено 10 секундами.
- Самообновление вызывало `Application.Shutdown()`, обходя ожидание сохранения. Теперь оно закрывает окно обычным путём. Новый процесс запускается после сохранения и завершения старого процесса, когда освобождена блокировка desktop.
- CLI-обновление запускало новое окно до закрытия старого и принудительно завершало старый процесс через 1,5 секунды. Теперь оно ждёт нормального завершения исходных окон; ошибка или отмена закрытия не приводит к принудительному завершению и запуску конкурирующего окна.

## Одно окно для общего хранилища

Повторный запуск TerminalV показывает сообщение об уже открытом окне и завершается. Второе окно раньше могло заменить общий список сессий устаревшими данными; фоновый host также рассчитан на одно подключение. Desktop удерживает исключительный доступ к `desktop.lock` в каталоге базы до завершения приложения. После аварии блокировка освобождается автоматически; оставшийся файл не мешает следующему запуску. CLI и фоновый host эту блокировку не захватывают.

Старые версии не используют эту защиту: перед первым запуском обновлённой версии нужно закрыть все ранее открытые окна TerminalV. Проверки захвата, освобождения, независимых каталогов и ошибок открытия добавлены в `TerminalV.Data.Tests`; запускать их следует в CI или на другой машине вместе с проверкой повторного запуска desktop.

## Проверка без сборки

Из каталога `ui`, с установленными npm-зависимостями:

```powershell
node --test --test-concurrency=1 tests/session-persistence.test.js tests/session-management.test.js tests/notifications.test.js
```

Тесты используют настоящий xterm.js и SerializeAddon без браузера. Проверяются раннее закрытие, восстановление видимых и скрытых вкладок, последние байты перед закрытием, сохранение до получения replay, непрерывный вывод, удаление вкладки во время ожидания, ошибка сериализации и обработка BEL. Рабочая база и фоновые процессы пользователя не используются.

Проверка WPF после сборки в CI или на другой машине:

1. Открыть несколько вкладок, переименовать и скрыть одну; вывести узнаваемый текст и сразу закрыть окно. Открыть снова и проверить список, названия, расположение и вывод.
2. Повторить закрытие сразу после открытия приложения.
3. Запустить непрерывный вывод, затем перезагрузить Windows. Проверить сохранённые вкладки и недавний снимок; процессы после перезагрузки не восстанавливаются.
4. На изолированной тестовой базе вызвать ошибку записи и закрыть окно. Проверить сообщение об ошибке и сохранение открытого окна; после устранения ошибки повторить закрытие.
5. Повторить проверку сохранения при обновлении из интерфейса и CLI. При заблокированной базе старое окно должно оставаться открытым, новое не должно запускаться.
6. При открытом TerminalV повторно запустить desktop. Должно остаться одно окно, без изменений списка сессий; после закрытия оно должно открываться снова.

Workflow `.github/workflows/session-persistence.yml` собирает desktop и UI на Windows, запускает проверки SQLite/блокировки desktop, изолированного host/ConPTY, таймингов xterm и браузерные проверки сессий. Он запускается вручную, для pull request и при push в `main`; публикацию релиза не выполняет. В текущем локальном исправлении этот workflow подготовлен, но ещё не запускался. Проверки реального закрытия WPF и обновления остаются отдельным шагом перед релизом.

## Отдельные ограничения

Одновременное подключение desktop и шлюза к фоновому host требует отдельной доработки: host обслуживает одно подключение. Принудительное завершение приложения или Windows не гарантирует финальную запись: остаётся последний успешный снимок. Эти сценарии не проверены тестами WPF в рамках данного исправления.

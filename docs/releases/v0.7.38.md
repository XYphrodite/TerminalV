# TerminalV v0.7.38 — ED3 от Kimi не паркует вьюпорт вверху

- Исправлены прыжки наверх при работающем Kimi без открытого поиска. Inline TUI делает полную перерисовку кадра как `?2026h` + `2J` + `3J` + `H` и заново печатает интерфейс: `ESC[3J` стирает scrollback, xterm обнуляет `ydisp` и может оставить `isUserScrolling` залипшим, из-за чего пересобранный кадр (сотни строк) остаётся вверху (`viewportY=0` при большом `baseY`) вместо живого экрана. После разбора записи с `3J` вьюпорт возвращается на живой экран (`scrollToBottom`, включая повтор на следующем кадре против гонки со скроллбаром) в `ui/src/notifications.js`. Обычный вывод без `3J` позицию читателя истории не трогает.
- Новый fixture `ui/tests/scroll-jump.fixture.html` (4 сценария: следит за выводом, читает историю, `3J` в раздельных записях, вывод без `3J`) и юнит-тест в `ui/tests/notifications.test.js`. Без фикса «ED3 full redraw after reading history lands on the live screen» падает (`expected 177, got 0`), после — зелёный. Соседние scroll/search/sync-тесты и весь `selection.test.js` — 240/240.
- Диагностика `scroll-jump`/`scroll-esc` из 0.7.34 оставлена: если увод наверх повторится уже без `2J`/`3J` перед событием, строки из `%LocalAppData%\TerminalV\diagnostics.log` покажут виновную последовательность.
- Видимая версия Android совпадает с Windows: **0.7.38**. VersionCode 34.

Для полной синхронизации нужны **Windows 0.7.38** и **TerminalV Mobile 0.7.38** (VersionCode 34).

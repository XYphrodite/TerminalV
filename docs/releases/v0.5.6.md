# TerminalV v0.5.6

## Быстрая вставка большого текста

- Исправлена медленная вставка большого объёма текста в чат `muse` и другие TUI. Ранее большой буфер (`>10–100 КБ`) уходил одним JSON-сообщением и одним `StreamWriter.Write` в ConPTY-трубу, блокируя `NamedPipe`/`FileStream` и UI-поток WebView2 пока конcоль не дренирует буфер.
- Теперь вставка режется на чанки: `ui` — по 4000 символов (`write-chunk.js`, `chunkText` с защитой суррогатных пар `😀`), `SessionClient.Write` — по 4000, `ConPtySession.Write` — по 8192. Каждый чанк — отдельное `write` сообщение, `lock(_writeGate)` держится только на время записи чанка, пайп успевает дренироваться между чанками. `ESC[200~`/`ESC[201~` (bracketed paste) сохраняются как единый поток, разбитый по границам чанков.
- Кириллица, эмодзи, многострочный текст и `bracketed paste` (исходный `term.paste` из `xterm.js`) сохраняют точный round-trip: `chunks.join("") === payload`, суррогатные пары не режутся.
- Ввод с клавиатуры не затрагивается (мелкие `onData` по 1 символу идут как один чанк). Протокол фонового хоста, OSC `9;9` для отслеживания папки, профили и WSL не менялись.

## Обновление

Выполните `TerminalV update` или нажмите **Обновить** в приложении. Для ручной установки доступны self-contained ZIP для Windows x64 и файл SHA-256.

Перезапуск фонового хоста не требуется, достаточно перезапуска окна. Старый хост продолжает обслуживать живые сессии до перезагрузки Windows.

## Проверки и пакет

Релизный ZIP должен пройти проверки через `scripts/verify-package.ps1`:

- `dotnet build -c Release` — 0 ошибок MSBuild, `BuildUi` (Vite) успешно.
- `TerminalV.Package.Tests` — 21 проверка ZIP/CLI/обновления/отката.
- `TerminalV.Pty.Tests` — 32 проверки (31 прежних + 1 новая `large paste is chunked into bounded writes`): кириллица, `🖥`/`😀`, `ESC[200~` payload, 100 КБ за `<500ms`, каждый чанк `<=4000`.
- `TerminalV.Data.Tests` — 11 SQLite.
- `TerminalV.Shell.Tests` — 9 Windows-ярлыков.
- `installer-shortcuts.tests.ps1` — 8 сценариев установщика.
- `ui` — `node --test tests/*.test.js` с `TERMINALV_TEST_APP_ROOT` на распакованный `wwwroot`: 185 Node/браузерных (180 прежних + 5 `write-chunk.test.js`).

Итого: `185 + 32 + 11 + 21 + 9 + 8 = 266` проверок без пропусков при заданных `TERMINALV_TEST_PWSH`/`TERMINALV_TEST_WSL_DISTRIBUTION`/`TERMINALV_TEST_CODEX_PATH`. Оба запускателя возвращают `0.5.6`; ProductVersion EXE и версия в упакованном интерфейсе — `0.5.6`.

Браузерные app-fixtures загружают интерфейс из распакованного ZIP. Реальные `.lnk` проверялись в изолированных временных папках. Пользовательские ярлыки, установленная копия, рабочий хост и база не изменялись. Ручная проверка WPF/WebView2-окна не проводилась.

Пакет после сборки:

```powershell
.\scripts\publish.ps1 -OutputDirectory artifacts/release-v0.5.6
.\scripts\verify-package.ps1 -Package artifacts/release-v0.5.6/TerminalV-win-x64.zip
```

Ожидаемый вывод: `TerminalV-win-x64.zip` (~66 МБ, self-contained `win-x64`) + `TerminalV-win-x64.zip.sha256` рядом, логи `verification-*` внутри каталога пакета.

# TerminalV v0.6.1 — фикс зависания вставки 4K в Muse + диагностика

## Исправлено зависание

- 4K многострочной вставки (`Ctrl+V` / правый клик → диалог → `term.paste` → `ESC[200~...ESC[201~`) в `muse` со сплитом 4 панели вешала вкладку: ввод и шорткаты не реагировали, окно крутилось, другие вкладки живы. Второй раз — весь `TerminalV`. Причина — `ConPtySession.ProcessWriteQueue` держал `lock(_writeGate)` во время блокирующего `StreamWriter.Write` в ConPTY-трубу, `SessionHost.Serve` не мог `Enqueue` второй чанк.
- Теперь очередь (`_queueGate`) и труба (`_writerGate`) раздельны: `enqueue` никогда не ждёт `WriteFile`, pump пишет под отдельным локом, `Dispose` чистит очередь. Добавлен тайминг `slow >50ms` для `Write chunk`.

## Диагностика вставки

- Новый `Diagnostics/Diag.cs` → `%LOCALAPPDATA%\TerminalV\diagnostics.log` (ротация 5MB, дублирует `Debug.WriteLine`). Логи: `pty Write enqueue`, `pty Write chunk slow`, `client/host Send gate contention`, `bridge write async/sync ms`, `ui postWrite async + watchdog 2s`, `paste clipboard/term.paste start/done`.
- UI шлёт `diag` через `post({type:"diag"})` → `TerminalBridge` → файл. Путь для хвоста: `Get-Content $env:LOCALAPPDATA\TerminalV\diagnostics.log -Tail 100`.
- Починён `Ssh/ITailscaleConnector.cs` / `TailscaleStubConnector.cs` / `TsnetSshSession.cs` — добавлен `using System.IO` (сборка падала на `Stream`).

## Проверки

- `tests/TerminalV.Pty.Tests` — **25/25 pass**, новый durable `concurrent 4k paste writes don't deadlock queue lock (split 4 panes reproducer)` — 4 потока ×8 вставок `4000` в `cmd.exe` ConPTY `<2000ms`.
- `ui/tests/write-chunk.test.js` — **6/6 pass**, `pane-layout.test.js` — **9/9 pass**.

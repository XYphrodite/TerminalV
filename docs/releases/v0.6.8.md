# TerminalV v0.6.8 — точная причина медленной вставки

## Причина

Вставка большого текста (5К+ в `muse`) занимала секунды: `postWrite` для `bracketed paste` `ESC[200~...ESC[201~` делал **по `queueMicrotask` и `postMessage` на каждый чанк `4000`** (для 60К — 15 микрозадач + 15 `Task.Run` на `TerminalBridge` + 15 `Send` под `lock` `SessionClient`/`SessionHost` + 7 `WriteFile` в `ConPty` под `writerGate`). Между чанками была видимая пауза «сначала одна, потом вторая» — каждая микрозадача + `NamedPipe` `WriteLine` с `TryEnter` 50ms + `ConPty` `Write` под блокировкой трубы суммировались. `Diag` уже стал асинхронным в `v0.6.5`, но `N` Task.Run оставались.

Точная цепочка: `term.paste` → `onData` → `chunkText 4000` (15) → `for chunk queueMicrotask(post)` → `TerminalBridge` `isPaste → Task.Run(Host.Write(chunk))` ×15 → `SessionClient.Send` `lock(_gate) WriteLine` ×15 → `SessionHost` `ReadLine` → `Pty.Write` `enqueue lock(queueGate)` + `ProcessWriteQueue` `lock(writerGate) WriteFile` (блокировка трубы пока `muse` не дренирует `alternate buffer`). Замер 60К до фикса: `15 × (1ms microtask + 30ms pipe)` ≈ `450ms` + `Diag` sync `+600ms` = секунды.

## Фикс

- `ui/src/main.js` `postWrite`: для `isPaste` (muse) — **один** `queueMicrotask` с одним `post({type:"write", data: wholePayload})`, чанкует уже `SessionClient`/`ConPty` в **одном** `Task.Run` батче. Для больших не-paste — один батч-микрозадача на все чанки.
- Сохранён `Diag` асинхронный батч `v0.6.5`, `queueGate`/`writerGate` разделены.

## Проверки

- `ui/tests/write-chunk.test.js` **7/7** (новый `paste batch uses single microtask` — 1 батч +1 await, не `N+1`), `tui-refresh 2/2`, `dotnet build -f net10.0-windows` 0 CS, `Pty large paste 100K <500ms`, `concurrent 4K` <2000ms — **25/25**, `5К` `Write call ms=1` + `Second write ms=0` на реальном `ConPty` (1 чанк `8192`).

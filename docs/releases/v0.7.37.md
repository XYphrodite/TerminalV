# TerminalV v0.7.37 — поиск не дёргает вьюпорт при смене буфера

- Исправлены самопроизвольные прыжки наверх при работающем Kimi: пока панель поиска открыта, каждый вход/выход TUI из alternate screen (`?1049h/l`) заново запускал `findNext` к первому совпадению в самом начале истории. Фоновое обновление при смене буфера теперь только освежает подсветку и счётчик, а позицию возвращает на место (внизу — `scrollToBottom`, в истории — та же строка); явная навигация (Enter, стрелки, ввод) двигает вьюпорт как раньше (`ui/src/terminal-search.js`).
- Новый тест `buffer switches refresh matches without moving the viewport` (`ui/tests/terminal-search.fixture.html`): до фикса падал `Expected 112, got 0`, после — зелёный. Проверена широкая батарея последовательностей (спиннеры, `?2026`, OSC 8, `2J`, `3J`, `RIS`, скролл-регионы, kitty-клавиатура, bulk 1500 строк) — без открытого поиска вьюпорт стоит внизу.
- Диагностика `scroll-jump` из 0.7.34 оставлена: если увод наверх повторится с закрытым поиском, строки `scroll-jump`/`scroll-esc` из `%LocalAppData%\TerminalV\diagnostics.log` покажут виновную последовательность.
- Видимая версия Android совпадает с Windows: **0.7.37**. VersionCode 33.

Для полной синхронизации нужны **Windows 0.7.37** и **TerminalV Mobile 0.7.37** (VersionCode 33).
